# 匿名验证摘要

本摘要保留已完成的数值、跨节点和性能结论；账户、主机、节点、作业编号及部署路径不纳入公开文档。
详细原始运行记录单独保存。结果只适用于下列硬件、依赖、编译策略和冻结工作量，
不承诺其他平台或任意小网格具有相同加速比。

## 环境与基准

| 项目 | 已验证配置 |
|---|---|
| CPU | Hygon C86 7285，单节点32物理核、每核1线程 |
| DCU | 每节点4张 Radeon Pro VII / Vega 20，gfx906，每卡约16 GiB |
| MPI | Intel MPI 2021.9，32个真实科学rank |
| 设备库 | DTK 26.04，HIP 6.3.26113，本地hipFFT 1.0.14 |
| CPU FFT | FFTW 3.3.10 MPI，SSE2/AVX/AVX2 |
| 后处理 | Python 3.11.3、NumPy 1.24.3、Pillow 9.4.0；保留原Coordinator JAR与OVITO链路 |
| 执行位置 | Slurm Debug批作业分配的计算节点 |

CPU基准为提交 `c86efb51cf03086fb98897ab8abfe2704a62096e` 的原始 `src/pfc.c`，
源码未因命名或计时改写。CPU/DCU主机同用 `-O3 -march=native -ffp-contract=off -Wall`；
设备同用FP64、`-O3 -ffp-contract=off`，不启用fast-math。
FFTW配置为 `--enable-mpi --enable-shared --enable-sse2 --enable-avx --enable-avx2`。
只链接本地 `-lhipfft`，不混用OpenMPI ABI的hipFFT-Mp。

## 冻结工作量

| 验证 | 网格 | 每阶段步数 | MPI/设备资源 |
|---|---|---|---|
| 短程数值与流程 | 256² | 128 | 单节点32rank、4 DCU；与原CPU比较 |
| 跨节点 | 同一256² | 128 | 双节点、总32rank，每节点16rank及4 DCU；复用短程CPU结果 |
| 完整性能配对 | 4240² | 2000 | 同一独占节点各运行一次全新CPU与4 DCU，均32rank |

共同种子为 `34789847`。性能算例使用100个晶核、半径参数2、诊断/保存间隔1000/2000；
其余物理参数见 [research.md](research.md) 第10节。保留原转换尺度
`0.7 0.7 7.3 2.46`，对应名义尺寸 `100.01753424657535 × 100.01753424657535 nm`。

## 完整PFC性能

| 阶段 | 原CPU（秒） | 四卡DCU（秒） |
|---|---:|---:|
| 第一阶段 | 220.58 | 40.06 |
| 第二阶段 | 237.58 | 43.06 |
| 两阶段合计 | 458.16 | 83.12 |

完整两阶段加速比为 **5.512030798845044**，超过 `>=5.0` 门槛。
历史验收计时覆盖完整MPI启动至退出，包含初始化、FFT规划、推进、盒优化、通信、日志及密度落盘；
图片、Java Coordinator、OVITO及LAMMPS转换不在计时内。
日常脚本不保留该外层计时或验收流程，求解器自身逐步计时仍输出。

## 数值与兼容性

密度逐样本判定式保持 `abs(DCU-CPU) <= 1e-6 + 1e-5*abs(CPU)`；
科学诊断保持 `1e-8 + 1e-6*abs(CPU)`，没有放宽阈值。

| 密度检查 | 最大绝对误差 | 最大容差比 | 超限样本数 |
|---|---:|---:|---:|
| 第一阶段初态 | 0，文本逐字节一致 | 0 | 0 |
| 第一阶段末态 | 1.0000000000287557e-7 | 0.03427466413498308 | 0 |
| 第二阶段初态 | 2.000000000335067e-8 | 0.011627270858815614 | 0 |
| 第二阶段末态 | 1.3000000000373824e-6 | 0.9183166262961105 | 0 |

最大容差比为逐样本 `abs(DCU-CPU)/(1e-6+1e-5*abs(CPU))` 的最大值。
两阶段原六列科学输出中的 `dx/dy/f/p` 在原9位小数下误差为0。
CPU/DCU最终转换原子数均为 **388638**，LAMMPS数据原子数量一致。
每阶段均有2000条实际推进计时；第二阶段有20条原调度的盒优化计时，包含终止时刻。
短程及跨节点对照通过；旧重启引用、安全命名、防覆盖和最多3帧灰度检查通过。

独立静态审阅未发现原非线性项、谱更新、归一化、每100步刷新、`fp()`恢复q/P、
主机A/B、32个科学rank初始化/局部重启统计及盒优化公式/调度的变化。
同卡D2D优化仅复制原区块字节，其余同节点交换使用共享主机内存，跨节点使用主机暂存MPI。

原CPU自身的一次重复对照也全部位于同一容差内；其第二阶段末态仍存在保存值差异。
这说明验收针对冻结的工程容差，不能将文本一致性当作内部FP64逐位一致的证明。
没有执行全量测试、参数扫描或生产时长验证；静态审阅不能替代其他硬件上的实际验证。
