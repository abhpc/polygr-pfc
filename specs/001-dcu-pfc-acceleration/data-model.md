# Data Model: DCU 双精度 PFC 加速

公共安装与直接Shell编译、运行命令见[README](../../README.md)。Slurm/Debug仅约束本会话代理的
受管集群执行及私有部署；公共用户不以此为安装前提。下文调度设计保留本次实现/验证背景，
科学公式、FP64、固定输入与容差不受此范围澄清影响。

日期：2026-10-20。本文定义运行时数据及验收记录，不引入数据库或新物理输入格式。
接口见 [CLI 契约](contracts/cli.md)及[数据与日志契约](contracts/data-and-logs.md)，
技术决策和依据见 [research.md](research.md)。

## 1. 原 CPU 基准与科学划分

| 字段 | 含义与约束 |
|---|---|
| `baseline_commit` | 固定为 `c86efb51cf03086fb98897ab8abfe2704a62096e` |
| `baseline_source` | 该提交的 `src/pfc.c` 原始 Git blob；构建前记录内容哈希 |
| `host_flags` | CPU 基准与 DCU 主机同用 `-O3 -march=native -ffp-contract=off -Wall` |
| `mpi_size` | V1/V2/V3 均为 32 个实际 MPI rank，不引入虚拟科学 rank |
| `slabs[rank]` | 原 FFTW 查询给出的 `lH,lh0,lW,lw0,alloc_local` |
| `real_stride` | `2*(W/2+1)` 个 double；仅每行前 W 个值是物理样本 |

实场归属为 `[lh0,lh0+lH) × [0,W)`；转置后的频场归属为
`[lw0,lw0+lW) × [0,H)`，第一维为非负 kx 下标。不得用简单整除重造 FFTW 划分。
元数据须检查全局覆盖、无重叠和容量溢出；空 slab 保留在集合通信中，跳过本地零长度变换。

CPU/DCU 同一配对须具有相同 rank 顺序和 slab 描述。原初始化类型 0 的随机流、类型 2 的
局部均值/极差均依赖此划分；相同种子本身不能证明科学初态相同。
类型 1 保留 rank 0 生成晶核、广播及原主机初始化公式。

## 2. 科学运行配置

| 字段组 | 内容 |
|---|---|
| 身份 | 独立运行目录、原输入路径、原前缀、安全输出前缀、阶段名、R 块序号 |
| 调度 | 受管代理仅在Slurm批作业执行；该部署脚本头部显式声明 `#SBATCH --partition=Debug`，无其他分区或回退 |
| S | 非零整数种子；验收固定 `34789847`，原输入仍保留其既有含义 |
| O | 原诊断间隔 `T_print` 与写场间隔 `T_write`，均为正整数 |
| A | 正整数 `W,H`，以及由基准定义的 MPI slab 描述 |
| I | 原类型 0/1/2；噪声参数、晶核参数或重启路径与局部重标度参数 |
| M | FP64 `alpha,beta,gamma,delta,c`，含义与原模型一致 |
| R | 非负 `T`、正 `dx,dy,dt` 及原 `T_optimize`；优化距离 d 按原生命周期保存 |

解析不得改变既有标签、参数顺序、单位和物理解释。I=2 保存精确原路径及实际解析到的路径；
每个原 rank 继续按本地实 slab 的均值、最小值和最大值执行原重标度。
局部极差为零或产生非有限值时明确失败，不以全局统计或替代公式修复。
每次求解器调用开始时 `d=1e-4`；同一调用后续 R 块不擅自重置原优化状态。

冻结的验证配置如下，V2 不新增科学算例：

| 验证组 | 网格 | 晶核 `N,R` | 两阶段 T | `T_print,T_write` | 资源 |
|---|---|---|---|---|---|
| V1 | `256×256` | `16,2` | `128,128` | `64,128` | CPU/DCU 各单节点 32 rank；DCU 4 卡 |
| V2 | 同 V1 | 同 V1 | 同 V1 | 同 V1 | 总 32 rank，2 节点各 16 rank、4 卡 |
| V3（100×100 nm，原尺度名义100.017534 nm） | `4240×4240` | `100,2` | `2000,2000` | `1000,2000` | 同一独占单节点顺序运行 CPU/4 DCU，32 rank |

共同初始化为类型 1：`dx=dy=.7,l0=7.2552,p=.25,A=-.1`。
第一阶段 `M=(-.18,1,0,1,1)`、`dx=dy=.7,dt=.2,T_optimize=0`；
第二阶段读取各自第一阶段末态，`p=-.072,A=.1`，
`M=(-.15,1,.87,1,0)`、`dx=dy=.7,dt=1,T_optimize=100`。
CPU/DCU 使用相同输入字节，包括第二阶段的旧 `-t-` 文件引用。

## 3. 设备分配与 FFT 数据所有权

| 字段 | 内容与约束 |
|---|---|
| `global_rank` | MPI_COMM_WORLD 中的原 rank，决定科学 slab |
| `local_rank` | 同一节点内按共享内存 communicator 确定的本地 rank |
| `visible_devices` | 执行环境中可见且可用的设备集合，不假定物理编号连续 |
| `device` | 本地 rank 对分配设备数取模后选择的可见设备，并记录实际设备标识 |
| 单节点验收 | 32 rank、4 个不同实际设备，每个设备 8 rank |
| 跨节点验收 | 每节点 16 rank、4 个不同实际设备，每个设备 4 rank |

每个真实rank保留自己的主机科学slab、初始化及局部统计；同卡成员的设备数据与FFT工作区
由本组最低rank执行进程持有，以成员原slab顺序拼接，并显式保存global x/y映射。
每节点4个执行进程驱动4卡，不增加虚拟科学rank。上传、下载、诊断与A/B更新通过组内集合
分发原slab；逐步FFT仅在执行进程间转置，其他成员在下一次所需数据交换处等待。
设备共享不得使多个 rank 被误判为多张不同卡。CPU 资源固定 32 个物理核心，不靠
`OMP_NUM_THREADS` 为原纯 MPI 求解器虚构线程并行。

| 数据 | 精度、布局与权威副本 |
|---|---|
| 主机初始 `q` | 原 padded 实 slab；原初始化完成后上传到设备 |
| 设备实场 `q` | FP64，推进期间为密度的权威副本；输出/诊断时按需下载 |
| 设备持久谱场 `P` | FP64 complex，组内原kx slab拼接且显式global x映射，保持 `F(psi)/(W*H)` |
| 设备工作场 `Q` | FP64 complex；非线性 FFT、诊断算子和逆变换按原调用顺序复用 |
| 设备 `A,B` | 原C循环/主机exp计算的FP64系数按原频slab上传并聚合；B已含原 `1/(W*H)` |
| FFT 计划及工作区 | 每卡执行进程的聚合批次、原W/H长度；不隐式缩放、不以非FP64替代 |
| 转置缓冲 | 可复用设备打包区及页锁定主机区，描述与slab元数据一致 |
| 主机诊断数组 | 下载原密度与滤波结果，供原逐行自由能/密度累加和原 MPI 归约 |

正 FFT 的状态顺序为：实 y slab → W 向 D2Z → 按目标 kx slab 打包 →
D2H → 主机 MPI_Alltoallv → H2D → 转置 kx slab → H 向 Z2Z。
逆 FFT 反向执行。MPI 只接触主机指针，以双精度分量计数；检查容量、计数及位移溢出。
不得将 MPI 不支持的设备指针传入通信，也不得忽略空 slab。

生命周期为：配置 slab/分配 → 创建计划 → 原主机初始化 → 上传 →
按原调度推进、诊断、优化和保存 → 完成设备操作 → 释放资源。
`fp()` 恢复实场并重建 P，因而诊断不是纯查询；盒优化仍为主机原五次采样和原插值公式。
每次 `t%100==0` 的推进前谱刷新及终止时刻的盒优化均不可省略。
周期刷新保留在GPU，不增加物理运算或额外刷新。

## 4. 密度帧与灰度图片

| 字段 | 约束 |
|---|---|
| `source_prefix` | 原输入 basename 的文件系统字节；目录部分保持原路径 |
| `safe_prefix` | 仅保留 ASCII `A-Z,a-z,0-9,_,-`，其他每个字节替换为 `_`；空前缀拒绝 |
| `step` | 不补零的非负十进制整数；沿用原保存时刻 0..T |
| `density_path` | `<safe_prefix>-<step>.dat` |
| `samples` | 无表头，恰有 `W*H` 个有限实数；按全局 y 行、行内 x 顺序排列 |
| 序列化 | 保持原 `%e` 密度文本语义，不以提高输出位数改变第二阶段重启量化 |
| `image_path` | `<safe_prefix>-<step>.png`，8 位单通道 L 图，尺寸 `W×H` |
| 图像映射 | 每帧独立 min/max 线性映射，四舍五入至 0..255，再上下翻转；常量场全黑 |

C 与 Python 使用相同字节规则，不能分别按字节和 Unicode 字符产生不同安全前缀。
不同原前缀的规范化冲突、阶段冲突和独立运行已有目标均须明确失败；不写旧名副本。
同一调用的后续 R 块可按原行为重写本调用创建的同一步文件，不能借此覆盖调用前已有结果。
精确重启路径存在时优先使用它；仅在缺失且符合已知旧 `-t-<step>.dat` 模式时，
按同目录安全新名称回退并记录映射。具体 CLI、帧选择和冲突处理见
[CLI 契约](contracts/cli.md)。

## 5. 时间与原科学诊断

原六列科学诊断仍为 `t,elapsed,dx,dy,f,p`，保持原时刻及格式，不因逐步计时增调 `fp()`。
新增固定字段记录以 `PFC_TIMING` 标识，与科学诊断分开。

| 字段 | 约束 |
|---|---|
| 归属 | `phase` 为阶段安全前缀；`block` 为从 1 起的 R 块序号 |
| `kind` | `init,step,optimize,total`；init/total 按 invocation 归属 |
| `step` | 推进 `t→t+1` 标为 `t+1`，每块恰有 `1..T`；0 不虚构推进记录 |
| `seconds` | FP64、有限、非负秒数；包含完成的 FFT、数值推进与原有 MPI 等待 |
| `cumulative_seconds` | 从本 R 块开始至该步完成的墙钟秒数，包含期间优化/诊断/I/O；单独 MPI_MAX |
| 优化时间 | 单列原边界 t 上的优化，包含可能的终止优化，不并成额外推进步 |
| rank 聚合 | 每 rank 缓存本块步耗时；R 块结束按相同 step 使用 MPI_MAX 后由 rank 0 输出 |

关闭区间前必须确认设备工作完成；记录在 R 块结束汇总输出，不要求实时到达。
新增日志和时间归约计入求解器总时间。
内部初始化/总时间用于解释组成，性能验收另以外部计时包住每阶段完整 MPI 启动，
包括启动、规划、通信、传输、诊断、数据落盘和新增日志。不能把内部晚启动计时当成完整耗时。

## 6. 数值、性能与执行证据

每个验证配对保存一份证据记录：组别、基准提交与源码哈希、双方构建哈希及选项、
输入字节/哈希、种子、初始化参数、初态/末态文件、实际 slab、MPI 绑定、CPU/设备型号、
实际物理核心/设备数量、ISA/显存、模块与库版本、可选调度作业身份/分区、退出状态和日志路径。
本会话代理在受管集群执行时，实际分区必须为Debug；公共用户无该调度前提。

每个阶段的最终保存场逐项计算 `abs(DCU-CPU)`，判定式为
`abs(DCU-CPU) <= atol + rtol*abs(CPU)`；同时记录最大绝对误差、最大归一化容差比和超限数量。
不得只用平均误差掩盖局部超限。平均密度、自由能和 dx/dy 在原诊断时刻分别比较。

| 对象 | atol | rtol |
|---|---|---|
| 保存密度样本 | `1e-6` | `1e-5` |
| 平均密度、平均自由能、dx/dy | `1e-8` | `1e-6` |

任何 NaN/Inf、维度或样本数错误、超限及最终转换失败均失败。最终转换还须记录 CPU/DCU
原子数并完全一致；第一阶段按守恒动力学审阅均密度，第二阶段不施加虚假的密度守恒条件。

V3 同一次配对收集末态与完整耗时。`T_CPU`、`T_4DCU` 分别为两阶段外部墙钟之和，
不计排队、构建、图片及原子后处理；仅在配对数值通过且 `T_CPU/T_4DCU >= 5` 后性能通过。
V2 复用 V1 CPU 证据，不增加第二个 CPU 算例；导出检查最多选择三帧，不扩大模拟集合。

证据状态为：已冻结 → 已启动（调度器可选）→ 完成/失败 → 数值通过/失败 →
性能通过/失败。未执行项保留未验证；失败只能触发已定位原因的定向检查，不能扩大为全量测试。
